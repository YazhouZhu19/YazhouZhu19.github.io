# GitHub projects and Google News discovery

The **GitHub projects** and **Models & progress** entrances sit beside the full paper library. Their independent snapshot is `data/research-signals.json`; neither source is inserted into the paper archive or counted as a paper in the macro dashboard. Browse by text, publisher/owner and dates; compare up to three repositories by license, push/release dates, archived state and stars. Stars are a snapshot of attention, not research quality. Code licensing does not establish permissions for model weights, data or clinical use.

## Collection and provenance

`npm run collect:signals` collects public GitHub REST metadata, short README excerpts and the latest stable release, plus Google News public search RSS results for medical-imaging model/research announcements in English and Chinese. GitHub discovery combines seed projects with a versioned catalogue of 18 research directions/tasks and 24 queries in `lib/github-discovery.ts`. The catalogue covers segmentation, detection, classification, reconstruction, registration, radiomics, prognosis, image–language/report generation, foundation models, self-supervision, domain adaptation, interactive annotation, pathology, retinal imaging, ultrasound, 3D imaging, datasets and toolkits. Searches use both GitHub best-match and recently-updated ordering, with a shared bounded request budget allocated across the groups. Repository names deduplicate across searches and retain all matched discovery groups. These groups describe retrieval provenance, not verified research capabilities or quality labels. News discovery uses Google, not a visitor's browser history. The RSS endpoint is a best-effort public discovery interface, not a guaranteed Google developer API. Google's Custom Search JSON API is closed to new customers ([official notice](https://developers.google.com/custom-search/v1/overview), checked 2026-10-14).

Google results retain the named publisher, publication date, discovery URL and Google result link. Search titles and snippets are explicitly labelled `search-snippet`: they are not verified original article text. `originalUrl` remains null unless a public original URL is actually available; Google is not presented as the publisher. The initial collector does not claim to have verified publisher articles or their model-performance claims. Browsing offers an external Google News search for further discovery; those results are not automatically added to the snapshot.

The existing GitHub workflow invokes both collectors. Signal endpoints that last completed successfully with the same query/catalogue version are cached for six hours; `--force` refreshes them immediately. `--news-days N` changes the Google news discovery window (default 365 days). `--github-only` refreshes GitHub while retaining news records and their check times. `--input PATH --output PATH` support reviewable collection into a separate file; `--init` explicitly permits a missing initial input. `GH_TOKEN` or `GITHUB_TOKEN`, when present, is sent only to `api.github.com`. There is no browser-side token or shared AI secret.

Requests, response sizes and result counts are bounded. Existing records survive source failures and refreshes. Each endpoint records its real check time, last successful check, received/retained counts and errors. A cached source keeps its original check time. All-source failure records fresh errors and returns a failure status; malformed/oversize input or unexpected fatal failure cannot replace the archive with empty data. CI checks freshness and retained IDs, then verifies that the published signal bytes match the source snapshot. The browser validates the schema and 4 MiB size ceiling, retains its last valid snapshot on failure and loads signals independently of papers.

GitHub search responses supply repository metadata without an extra request for every candidate. README/release enrichment is bounded and rotates across collection cycles; missing enrichment remains unknown. Authentication permits a larger request budget, while the unauthenticated path respects a smaller budget and slower search pacing. Rate-limit failures use bounded handling and preserve the archive. The old 18-project ceiling has been removed; the shared snapshot size/schema limits still apply.

The GitHub library exposes a direction/task filter with actual collected counts, links to the configured queries, and each repository’s matched groups. Counts can overlap across groups. Selecting a group also limits the candidates passed to its AI panel. This filter does not add a fixed taxonomy to the independent Research outlook AI workflow.

## AI and evidence limits

Each source page can analyze its filtered records, with optional paper evidence. **Research outlook** and the independent-question window allow papers, GitHub and news to be selected together, with their own dates and forecast horizon. These use the existing local, free-cloud and paid AI choices; no separate model download is needed beyond the selected model's normal first use. Cloud analysis sends only the selected public evidence and the entered question to the explicitly chosen provider. The provider/model is displayed in the result.

AI inputs carry an explicit evidence kind. Papers describe reported research, repositories describe implementation availability and a current maintenance snapshot, and news describes publisher claims or unverified search snippets. A paper, repository and announcement can describe one work and do not establish independent corroboration. Sampling balances evidence kinds and time buckets; counts and categories cannot establish field-wide prevalence or growth. Results separate observations, conditional forecasts, alternative explanations and proposed validation, with links to exact supplied evidence.

PI/team analysis includes external records only when the selected papers and those records share an explicit URL, DOI or arXiv identifier. The interface exposes this linkage. Neither a link nor a repository owner proves authorship, team membership, PI ownership or private research intent. A lack of matched signals is reported as missing evidence.

GitHub date filters use the latest push, release or creation date; news filters use the reported publication date. Mutable repository metadata and search snippets are eligible for AI only when their observation date is on or before the selected end day. The collector currently keeps the latest observation per record, not a historical time series: it cannot reconstruct past repository state, popularity growth or a past announcement's exact contents. Dates are not backfilled to fabricate retrospective predictions.

Automated tests cover schema/size rejection, malformed responses, bounded discovery, cache/error retention, cross-source sampling and historical cutoffs, exact PI linkage, typed AI payloads, citation rejection and zero-price cloud safeguards. A mocked cloud test verifies the request/response integration; it does not validate a real model's scientific interpretation.
