# AI research and team outlook

The workspace preserves the complete archive and personal data. The research dashboard remains the default macro overview. Direction and PI / team outlooks now use an explicitly invoked AI analysis to help readers formulate testable next steps from public papers. The outputs are conditional interpretations of the displayed evidence, not undisclosed PI plans, research-quality rankings or calibrated forecasts. The collector and macro dashboard retain their existing deterministic classifications and statistics.

## Models and execution

The default visitor option is **Qwen3-1.7B-q4f16_1-MLC**, running locally through WebLLM. Visitors can also choose **Qwen3-0.6B** (lighter) or **Qwen3-4B** (larger). These need no registration, API key or paid account. Approximate model downloads are 350 MB, 1 GB and 2.3 GB respectively, plus the runtime. Only clicking Analyze starts a download; subsequent runs can reuse the browser cache. One active model engine is reused for the same model and released when a different model is loaded. A WebGPU-compatible browser is required, with a desktop device and several GB of available GPU memory recommended. A smaller model reduces download size but may be less capable. Device support, memory, network access to model files and inference speed vary. Unsupported devices and failed local runs show an error and never silently call a remote provider.

A reader can instead choose **free cloud AI** and enter their own **OpenRouter API key** from a free account. This avoids downloading model weights and requires no WebGPU; it does not guarantee a particular latency. The default API route is `openrouter/free`. Selecting free cloud mode loads the official public model catalog without credentials or paper text. The selectable list includes only `:free` text models with zero input/output/request prices, JSON response support and sufficient context/output capacity. The catalog can be refreshed; a failed catalog fetch leaves the free automatic route available. Model availability and account quotas can change, and a listed model may have no endpoint matching the request's data-collection policy. Free calls also enforce zero model-price routing and never fall back to paid requests. Paid use is a separate, explicit mode requiring a model ID. Reports display the actual model returned by the service, including multiple models if the free route used different models across batches.

Official references, checked on 2026-10-14: [Qwen model card](https://huggingface.co/Qwen/Qwen3-1.7B), [MLC 0.6B files](https://huggingface.co/mlc-ai/Qwen3-0.6B-q4f16_1-MLC/tree/main), [MLC 1.7B files](https://huggingface.co/mlc-ai/Qwen3-1.7B-q4f16_1-MLC/tree/main), [MLC 4B files](https://huggingface.co/mlc-ai/Qwen3-4B-q4f16_1-MLC/tree/main), [OpenRouter catalog](https://openrouter.ai/api/v1/models), [free router](https://openrouter.ai/docs/guides/routing/routers/free-router), [limits](https://openrouter.ai/docs/api-reference/limits) and [personal API keys](https://openrouter.ai/settings/keys).

## Independent analysis windows

- **Library landscape** derives recurring research directions, tasks, methods and data applications from the supplied paper text. It has no preset direction or modality selector.
- **Custom research interest** accepts a natural-language question in Chinese or English, with its own date range. Questions do not become strict keyword filters. If the supplied sample lacks relevant evidence, the model should report that limitation rather than declare an unstudied gap.
- **PI / team analysis** uses only the public papers belonging to the chosen author-directory entry or saved watchlist. It has its own dates, optional focus question and forecast horizon.

Each window defaults to the latest 90 Beijing calendar days and offers a future horizon of 6, 12 or 24 months. The horizon is measured after the selected evidence-window end. Choosing a historical window therefore requests a conditional outlook from that date, not a validated historical backtest. Window settings and completed results survive paper-evidence drill-through in bounded page memory; refreshing clears them. A change to evidence, dates, question, locale or model invalidates the displayed result as appropriate. In-flight requests can be canceled; scope changes and unmounts abort the request and ignore stale completions.

The original ten collection interests, library filters and macro-dashboard labels remain in use. Removing preset direction controls from the AI page does not make the collected archive comprehensive or remove the collection queries' topic bias.

## Evidence selection and inference

Publication dates define the analysis range, never ingestion or backfill times. Invalid and future source dates are excluded. DOI, related DOI, PMID, arXiv/version and namespaced source identifiers connect records into distinct works for this analysis only. Inclusion uses the earliest valid known publication date. One source record represents each work, preferring an available abstract and published version; an historical analysis never reads a record published after its selected end. Original records, dates, versions and library counts remain unchanged, so source-record dates can differ from the grouped work's first-publication date.

The complete eligible scope includes unclassified papers. Each panel defaults to **Quick preview**, sampling at most **6 distinct works locally** or **12 through the API**. **Expanded analysis** samples at most **24 locally** or **80 through the API**. Reducing the sample can avoid multiple reading and synthesis calls, at the cost of less evidence coverage; quick preview is not a comprehensive landscape assessment. Sampling is balanced across publication-time and source strata. The UI reports eligible works, source records, sampled works and missing abstracts separately, and opens the exact sample for inspection. Equal turns across strata do not preserve corpus proportions. This supports exploratory reading, not estimates of whole-field popularity, dominance, growth or decline. Missing abstracts remain unknown evidence.

The prompt receives bounded public-source fields: paper ID, title, abstract, publication date, source and publication status, plus the analysis question and scope. Titles are capped at 500 characters and abstracts at 900, so these are not full-text reviews. It does not receive preset direction labels, saved-paper notes or the contents of personal watchlists. Paper text and the question are passed as untrusted data, not executable instructions.

Selected papers are processed sequentially in bounded batches, then observations are synthesized in pairs. Local and cloud batching both apply conservative context-size estimates. Oversized inputs fail visibly instead of silently adding papers beyond the model context. An analysis may therefore make several model calls. No inference starts automatically on page load or as a background refresh. Switching model or analysis depth invalidates the visible result and cancels any in-flight analysis.

## Results and validation

Each completed report names the actual model and generation time, gives a brief synthesis, and separates evidence observations, conditional forecasts, alternative explanations and concrete next steps. Findings can concern directions, tasks, methods, data, applications or research opportunities that still need verification. Each finding must cite at least one supplied paper ID, with links back to the original records.

The app validates the complete JSON structure, field sizes and citation IDs before displaying generated claims. Unknown, empty or duplicated citations and truncated output are rejected rather than repaired into apparently supported conclusions. Batch synthesis can cite only evidence preserved in its preceding observations. These checks establish traceability and output shape; they do not verify whether the model correctly read an abstract or whether its hypothesis will occur. Readers should inspect the cited text before forming research decisions. No certainty scores, automatic novelty claims or clinical-validity judgments are generated by the interface.

## PI / teams and legacy diagnostics

The user confirms names or ORCIDs and can filter a saved author's publication affiliation. Neither institution nor last authorship identifies a lab or PI. Public author discovery is a list of matching records, not a PI ranking or verified membership list. The model is instructed not to infer private plans, intent, resources, current roles or confirmed team membership from those papers.

The selectable directory follows the original dynamic author-discovery approach, with one list per research interest and name/ORCID/affiliation search. It uses classified papers with valid, nonfuture publication dates; default candidates need at least two library records and an ORCID or an unabbreviated name. Explicit searches may expose abbreviated names with a warning. Distinct ORCIDs and name-only identities stay separate. Filtering recomputes counts, tags and publication affiliations in the selected scope. Temporary author analysis reads only that entry's records, preventing name-only selections from silently absorbing records assigned to different ORCIDs. Saved personal teams retain full-library member matching and the three user-assigned purpose categories. No directory entry is automatically saved.

The old deterministic engine remains for expandable **paper trajectory and existing tags** diagnostics. It compares two adjacent 90-day windows and retains its source-composition, sample-size and publication-span checks before interpreting a difference. These counts and labels are observed metadata, not AI predictions. The previous rule-based forecast cards are no longer the direction-page or team-page AI output.

Earlier rule-based revisions and manual outcome notes remain untouched in `medical-research-monitor:assessments:v1`. They describe versions actually viewed under the old feature, with its original retention limits of twelve revisions per scope and forty scopes. New AI results do not write to that history, and old records are not relabeled as AI assessments. There is no fabricated historical backtest or automatic accuracy measurement.

## Privacy and persistence

Saved papers, reading notes and team lists keep their existing localStorage behavior and personal-backup format. Local AI runs on the device. The browser downloads model files but does not send the analysis papers or question to an inference service.

When the reader chooses OpenRouter and clicks Analyze, the selected public paper text and their entered question are sent to OpenRouter and its model provider. The personal API key authenticates that request and stays only in page memory; it is not saved to localStorage, the archive, URLs or analytics. Saved reading notes and private watchlist contents are not included. Questions themselves may contain personal information, so the API disclosure is visible before analysis. Clearing the key or refreshing removes it; questions and generated results are also session-only. There is no server-side personal tracking or background notification channel.

## Verification

AI evidence tests cover inclusive publication bounds, historical-version safety, linked-work deduplication, all-classification coverage, independent Chinese questions, exact author scopes, deterministic balanced sampling, complete scope fingerprints and bounded public-data prompt projection. Report tests reject invented, empty or duplicated citations and malformed or oversized output.

Client tests use controlled responses to check the fixed API endpoint, selected free-model routing, rejection of paid models in free mode, explicit paid selection, actual-model reporting, cancellation, sanitized errors, complete-response checks, batch boundaries, pairwise synthesis and cleanup after failure. Catalog tests reject malformed, charged, incompatible and undersized entries and verify credential-free fetching and cancellation. These automated tests do not demonstrate live cloud-provider availability, a successful call with a real personal key or real-model research accuracy. Browser compatibility and inference quality depend on the visitor's environment and should be assessed separately.

A local browser QA run on 2026-10-14 successfully loaded the real WebGPU model and analyzed two real papers with output passing structure and citation-ID checks. That confirms this execution path in the tested environment, not scientific accuracy: the model still misread a comparison in the source text. The interface therefore asks readers to verify cited passages and states that traceable citations do not validate the conclusions.

Existing collector, public-snapshot, personal CRUD, backup, trajectory and legacy-history tests continue to apply. The complete archive and macro dashboard are maintained independently of optional AI runs.
