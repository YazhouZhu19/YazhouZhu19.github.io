# 多年研究积累：证据与方法边界

## 原生应用接入（2026-11-17）

“分析”已使用原工作区导航与页面框架，公开路由为 `#/analysis`，旧 `#/outlook` 链接兼容跳转。旧方向筛选参数不再限制综合分析，也不覆盖用户在论文库中保留的筛选条件。默认展示已核查的小众积累快照；“主流研究方向”与全库词法初筛继续使用当前完整论文、开源、动态记录运行固定规则。

原生界面通过延迟加载的 `components/analysis-history-panel.tsx` 读取 `data/analysis-history.json`，内容与本轮离线 HTML 的历史证据一致，固定截至 2026-11-17。`scripts/analyze-research-history.ts` 同时写入可审计报告与这个不含原始摘要的展示文件。点击“运行规则分析”不会暗中刷新或重新标记该快照。快照校验测试比对审计内容和原始来源包哈希；扩充版本时须明确重新生成并核查。

界面沿用全局语义颜色、阅读字体、数据字体、间距和圆角变量；复用现有按钮、输入框、状态标签及分类标签页，支持明暗主题、移动端与键盘展开。没有 iframe，也不导入独立 HTML 的页头、背景或外部字体。`scripts/check-native-analysis.ts` 针对 `dist` 中的完整真实数据启动本地预览，检查分类、状态筛选、版本时间线、主流重算、移动端和模型请求，并保存实际界面截图。

本次补充采用定向检索与来源核对，收集论文、数据版本、公开代码维护事件，再交给确定性规则判断。证据包不保存模型生成的方向评分或“证据充分”标签。这批候选不是随机样本，不能用于估计整个医学影像领域的方向占比，也不能证明所有未入选方向缺乏积累。

## 本轮结果与可复算规则

历史规则版本为 `2026-11-17-history-v1`，实现在 `lib/longitudinal-analysis.ts`。本轮核查 14 个独立作品：脊髓 MRI 4 个、胎儿脑 MRI 4 个、QSM 6 个。预印本、正式发表版本及明确同作品标识合并；“独立作品”不表示使用独立队列。原始论文库中 5,330 个合格独立作品构成占比分母，14 个定向核查作品不混入分母。原标题和原始摘要命中窄领域词表的数量分别为脊髓 15、胎儿脑 21、QSM 7，不能把这个比例解释为全领域流行度。

所有门槛同时通过才输出“证据充分”，没有加权分数可以抵消证据缺口：

| 门槛 | 固定规则 |
| --- | --- |
| 库内低占比 | 补采前合格独立作品中占比 <10% |
| 多年论文 | 至少 3 个作品、3 个年份、730 天跨度 |
| 研究逻辑线索 | 至少 2 篇原始摘要命中问题、方法、验证与数值结果词法规则；排除未来计划与明确未验证表述 |
| 数据版本积累 | 同一数据家族的至少 2 个明确日期版本相隔至少 365 天；具有源记录支持的新增影像或标注，而非只变更元数据 |
| 代码维护 | 与所选论文明确关联、非归档，实际发布/提交覆盖至少 3 个年份和 730 天，最近事件不超过 365 天 |
| 证据链闭合 | 至少一个所选作品同时明确关联满足条件的数据集与代码库 |

数据版本按 GitHub owner/repository 核对家族；非 GitHub 数据需要显式的共同 concept DOI，不能按相似名称合并。参与者增加须和配对版本的参与者表计数、版本标识及新增影像路径证据一致；标注增加须有明确配对版本与已核实内容文件变化。日期必须精确到日，未来日期、未知日期不计入跨度；版本名称、仓库创建日期、记录修改时间不能代替事件日期。

脊髓 MRI 通过六项门槛：论文覆盖 2016–2024；Spine Generic 的 `r20200826` 与 `r20211125` 相隔 456 天，参与者表从 260 增至 267，相关合并请求有 51 个新增影像路径；2025 另有衍生分割结果更新。新增数据的合并时间和版本发布日分别记录，不能据此断言连续采集了 456 天。2024 神经根论文原文同时链接数据版本与 SCT 代码版本，形成明确链条。代码发布记录覆盖 2019、2020、2025、2026，实际提交更新至 2026-11-16。

QSM 和胎儿脑 MRI 保留“待补证据”。胎儿脑方向的自动重建代码有 2023、2024、2026 年已核实代码变更；但 FeTA 的未知日期版本及另一个独立的生物测量数据集不能拼成同一数据集的跨年版本。本轮胎儿摘要有 0 篇同时通过四类严格线索规则，主要缺少数值性能结果共现；这只是词法筛选未覆盖摘要，不能推断论文没有结果。所有全文链接、详细日期依据和真实缺口保存在证据包与离线页面中。

这轮新增门槛是可解释的工程筛选规则，不是已有文献中的命名算法，也未经独立人工金标准校准。回归测试检查反例、确定性与实现边界，不是准确率/召回率比较。既有 TF-IDF/BM25 候选关联保留，但不自动补足明确关联门槛。来源材料核对、规则执行与 HTML 展示均不调用大语言模型服务。

## 来源与日期

`data/research-history/*-evidence.json` 保存结构化事实，`data/research-history/raw/` 保存对应的摘要、元数据、正文链接、仓库响应或更新日志。论文来源为原始论文及 Europe PMC 的出版方摘要；数据版本优先依据作者更新日志；代码使用官方仓库 README、GitHub 发布和提交记录。采集时间与事件时间分开记录。

QSM 包包含 6 篇论文，出版年覆盖 2017、2021、2024、2025；官方 [QSMxT 仓库](https://github.com/QSMxT/QSMxT) 的发布记录覆盖 2021–2026，最近核实提交为 2026-11-16。仓库创建时间单独保存为 `2020-12-21T00:24:36Z`，不计作一次维护事件。

日期不能直接取所有 API 的同名字段。例如 [2025 年 QSM 管线比较论文](https://doi.org/10.1002/hbm.70187) 在 Europe PMC 的 `firstPublicationDate` 为 `2025-04-01`；原文 JATS 明确标注电子发表日期为 **2025-04-22**，本包使用后者。QSMxT 论文使用 2021 年在线发表日期，2022 年卷期不重复算一篇。

## QSM 的实际缺口

[共识示例数据](https://zenodo.org/records/7410454) 的 [作者更新日志](https://zenodo.org/api/records/7795492/files/Update_log.md/content) 明确给出：

| 版本 | 发布日期 | 可核查变化 |
| --- | --- | --- |
| v0.1.0 | 2022-12-10 | 初始 GRE 数据、处理输出和代码包 |
| v0.2.0 | 2023-03-03 | 修复脑掩膜空洞，更换 VSHARP 实现 |
| v0.2.1 | 2023-04-03 | 移除 Tikhonov 重建，补充 FANSI/MEDI 完整重建输出 |

三次发布只跨 **114 天**，不能满足至少 365 天的版本积累门槛；更新日志也没有报告新增受试者或新采集影像。文件哈希变化可以证明包有变化，不能单独证明新增研究数据。Zenodo 三个版本重复的 `publication_date` 及稍后的入库时间均不能代替更新日志的发布日期。

2016 QSM 挑战使用人体采集数据，2019 挑战使用模拟头部体模。两者没有被合并成同一数据集的连续版本。2025 年论文使用十年随访数据，也不等于公开数据集存在十年可追溯版本。因此 QSM 的多年论文与活跃代码证据可以展示，长期公开数据积累仍需补证。

## 关联与重复计数

TF-IDF/BM25 相似度用于找候选，不建立官方论文—代码关系。QSMxT README 明确引用它自己的方法论文；同主题的其他论文不能据此算作 QSMxT 使用记录。数据记录明确提到某论文、论文明确链接资源、或官方仓库明确引用论文，必须分别保留关联方向与来源。

同一论文的预印本与正式发表版本合并。不同 DOI 也可能共享一个实验：QSM 挑战设计论文与体模论文使用相关基准，不能声称是独立队列；共识文章属于指南，不能替代实证比较。跨年发表、版本数量和最近提交共同提供积累线索，不构成科学效果、可复现性或研究价值的充分证明。

## 证据包约定与更新

`schemaVersion` 标识包格式；`candidate` 描述收集范围；`sources` 保存 URL、发布者、来源类型、采集时间及可选原始快照路径。每篇 `papers` 保留 DOI、原始摘要、`publishedAt` 和 `publicationDateBasis`；每个 `datasets.versions` 保留版本、发布日期、日期依据、变化说明及 `sourceId`；每个 `code` 保存仓库 URL、结构化 `archived`/`createdAt`/`metadataSourceId`、官方论文链接、发布记录和维护事实。`limitations` 保留缺失与不能推出的结论。缺失值不填零，也不从文件名或标签猜日期；传输中被隐藏的占位符不得作为文件名展示。

目前证据包由来源核验后更新，尚无专门的“一键刷新研究历史”命令。已有 `npm run collect` 和 `npm run collect:signals` 更新各自的日常快照，不应表述为已自动刷新本目录。更新历史包时需重新读取其 `sources[].url`，保留原始证据，核对新增事件、数据内容变化、论文版本及关联，再重新生成页面。

现有导出与检查入口如下；命令列表是复跑入口，不表示本说明编写时已经执行或通过：

```sh
node --import tsx scripts/analyze-research-history.ts
node --import tsx scripts/export-integrated-analysis-html.ts
node --import tsx scripts/check-analysis-html.ts
npm test
npm run build
```

HTML 的输出文件名与输入时点以实际导出脚本为准。测试和构建结果应由当次运行报告提供。
